# Automation adapter golden scenarios

The candidate uses seven distinct record owners and correlation boundaries. A caller presents one immutable adopted Coven attempt and independently verified authority evidence. Psyche adopts its own execution key before assignment, and each producer retains control of its transitions. The fixture accepts only synthetic identities. [Field and source inventory](README.md#field-and-authority-inventory) · [Program criteria](https://github.com/OpenCoven/psyche/issues/18)

| Order | Object and transition owner | Exact handoff and allowed transition | Lost reply or conflicting observation |
|---|---|---|---|
| 1 | Coven scheduler owns definition revision and occurrence fence | Commit the canonical occurrence key with definition revision/digest and current fence generation. An eligible occurrence can be claimed only by Coven. | A mismatched fence blocks intake. Re-establish the generation with Coven. |
| 2 | Coven owns the automation run | Bind `runId` to occurrence and the selected principal, familiar, authority decision and runtime. Coven decides run settlement after it has the requisite evidence. | Retain the run ID and prior history across restarts. Transport acceptance cannot settle a run. |
| 3 | Coven owns a dispatch attempt | Bind `attemptId`, attempt number, adoption key and dispatch fence to this run. Persist the Psyche producer/key association before submitting. | On uncertain adoption, look up the same producer/key. A second key cannot fork the existing attempt. |
| 4 | Psyche owns orchestration adoption | Record exact bytes/digest, generated execution reference and initial event together. Re-delivery returns the retained response. | Missing evidence leaves adoption uncertain. Changed bytes conflict. A crossed lookup response cannot update the caller’s pending record. |
| 5 | Psyche owns task, lane and lease | Record dependencies and assignment identities under the execution. Every lane’s capabilities, scope and approval references must fit the accepted projection. | Reopen preserves the last committed lane and lease. A previously active lane needs fresh host evidence before redispatch. |
| 6 | The execution host owns its worker attempt | Bind the local assignment to the host’s immutable execution request and worker attempt. Preserve the original correlation through cancellation and recovery. | A lost worker or possibly surviving action stays recovery-required. Only the designated host can establish containment. |
| 7 | Psyche, worker host and Coven each own their issued evidence | Psyche correlates task, verification and ambiguity evidence in its result. Coven binds its own base receipt and the authority sidecar to the original attempt. | Retain exact source IDs, digests and permitted evidence projection. A missing or mismatched sidecar, artifact, or delivery acknowledgement cannot become verified success. |

## Scenario inputs and observations

Each row defines the stimulus and observable outcome a conforming adapter must demonstrate. An executable fixture is identified by runner. Rows that depend on a production producer identify the missing input or authoritative observation. A fixture-level result keeps its limited scope even when several rows use it.

## Transport and recovery rules for these vectors

The requester's journal records the producer, stable invocation key and delivered bytes before sending. Psyche commits an adoption response and the initial event in the same transaction. After a lost reply, the requester verifies the recovered producer/key, source occurrence/run/attempt and request digest against its retained record. A crossed or missing result leaves the request pending. Retrying the external action requires the responsible producer’s decision.

For this fixture, an event is identified by its producer/key/execution stream and positive sequence. A cursor is the highest contiguous sequence committed by an authorized subscriber on that stream. A page is bounded to eight events. Duplicate bodies preserve the cursor, a gap or changed duplicate rolls back the full delivered page, and a cursor ahead of retained history is refused. A fresh subscriber process reconstructs its cursor from the retained inbox. The fixture retains history for the duration of each case. A production reset after compaction requires an authorized snapshot and an explicit new cursor from the feed owner.

The worker reference in `replay-observations.json` represents a supplied observation. Only a real host can report whether it can still act. Reading retained evidence never assigns work or settles the Coven run. The final integration still needs authenticated status and subscription, bounded retention and privacy/redaction, negotiated schema versions, authoritative cancellation and receipt composition.
