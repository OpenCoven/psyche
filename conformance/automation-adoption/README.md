# Automation adoption and replay vectors

This executable design slice models the point where Coven has already adopted an automation attempt and asks Psyche to adopt one orchestration request. Run `python3 conformance/automation-adoption/verify.py -v` from a clean checkout. The runner uses Python 3.9+ and SQLite from its standard library. All IDs and authority evidence in the fixture are synthetic.

## Test interpretation

`verified-input.json` stands in for an independently verified producer projection. A real adapter needs the trusted producer, current fence, exact principal and project, verified familiar and Threads records, approval evidence, scoped runtime admission and a final validity/revocation check bound to adoption. The vector explicitly compares those fixture fields before the transaction and denies authority widening. It cannot establish actual authentication, containment or revocation ordering.

`request.json` is delivered as exact UTF-8 bytes, including the final newline. The candidate computes SHA-256 over those bytes for retained invocation identity. A second SHA-256 covers the UTF-8 brief. Neither digest changes the upstream producer's RFC 8785 digest rules. `result.json` is the adoption response. A successful adoption supplies stable correlation for lookup and subsequent events. It conveys no worker or automation terminal outcome.

The runner checks #18 scenarios 1–3, a lost acknowledgement and lookup on a fresh connection, plus selected identity, integrity, scope and expiry denials from scenarios 8–10. Eight concurrent deliveries through separate database connections leave one execution. A conflicting key preserves the original result. A timeout resolves against the original producer/key. Scenarios 4–7 and 12–20, upstream verification of 8–10, an actual restart of Coven in 11, terminal result/event/error contracts, and an exact released-artifact canary remain open. Production lookup and subscription must authenticate the caller, minimize returned evidence and bind the cursor to the authorized projection.

The other proposed operations are `status` for authorized snapshots, `subscribe` for duplicate-safe bounded replay with an explicit cursor reset, `request_cancel` for adoption of a cancellation request, and `reconcile` for a retained response after uncertainty. A cancellation acknowledgement cannot settle either producer's terminal history. An ambiguous external effect requires recovery and stays ineligible for automatic retry. Approval and event lifecycle vectors require the owning protocols before these operations can be qualified.
