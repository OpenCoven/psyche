# Experimental lifecycle v2

Psyche qualifies a synthetic adapter against two separately collected records. Its test sink issues a fresh opaque execution ID and commits an effect per handler invocation. The consumer supplies a separate read-only observer for its persisted request, native approval and exact terminal journal receipt. The owner agreement applies to this experiment. [Owner decision](https://github.com/OpenCoven/psyche/pull/41#issuecomment-7079261966)

From the producer checkout run `bash profiles/adapter-lifecycle-v2/qualify.sh /tmp/lifecycle-v2.pyz`. This packages two clean exports, checks each member and the committed archive pin, and runs the regression fixtures against the package. In the matching Build checkout install frozen dependencies and run `bash protocol-fixtures/psyche-lifecycle/v2/qualify.sh`. Its JSON reports the six-effect negative control, structured refusals, native terminal receipt hashes, and the execution ID across first delivery, restart and native rollback. The v1 package and Build command remain available for rollback.

The harness launches the adapter and the observer as separate processes in the scenario workspace. Each adapter call receives one JSON request on stdin and returns a JSON reply on stdout. The harness gives only the adapter a submit endpoint through the inherited file descriptor named by `PSYCHE_TEST_EFFECT_FD`. The actual synthetic handler writes one newline-terminated JSON object containing `request_id`, `request_digest`, `attempt_id`, `task_id`, `action_id`, `approval_id` and `approval_digest`. The harness commits the effect before replying with a fresh 36-character execution ID and newline. The consumer contract requires the native handler to persist the issued ID and its binding before acknowledging completion. The harness checks the records returned by the consumer-supplied observer. The parent compares independently retained acknowledgements with its SQLite ledger. The effect is the committed synthetic append. The offline wrapper and native observer belong to the consuming implementation.

The observer receives an `operation` of `effects` after each refusal and returns the ordered native `effects` list. For `binding` it returns that list, the original bytes in `request_hex`, the seven fields in `binding`, the original `refusal`, the native `state` and the journal receipt in `receipt_hex`. Each effect contains its persisted `execution_id` and complete binding. Terminal replies include that ID, the binding, state, receipt bytes and execution count. The Build observer checks each native handler append and the original approval request. For executed actions it also checks the approval resolution’s terminal journal receipt. Rollback inputs carry the original task and action IDs. Refusals carry a code and the number of already-observed executions. Ambiguous acknowledgement must remain unknown. This qualification runs trusted fixture programs and does not establish host isolation between mutually hostile processes. The child can read the sibling SQLite witness ledger. Agreement with the observer therefore cannot establish where the child obtained an ID. The consumer supplies the trusted observer and instruments its synthetic effect handler. Effects outside both the sink and that instrumented handler are invisible to this qualification. Restart means a new process reading the disposable workspace after the preceding process exits.

V2 adds no stable identity or execution authority. The affected repositories are Psyche and Psyche Build. Stable adoption awaits #12. [Ownership decision](https://github.com/OpenCoven/psyche/issues/12)
